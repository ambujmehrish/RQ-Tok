# Bifrost-Flow — Design Document

*Bifrost-Flow: a flow-matching, adaptive residual-quantized successor to Bifrost-1 for unified
multimodal understanding and generation.*

This document is the source of truth for the research design. It is written to outlive the
ephemeral dev container, so it is intentionally self-contained.

---

## 1. Research problem (unchanged from Bifrost-1)

Integrate high-fidelity image generation into a **pretrained MLLM** while
(a) preserving its reasoning / understanding ability and
(b) avoiding single-architecture-scale training cost,
by **bridging a frozen MLLM and a pretrained generative renderer** through a latent interface.

We keep Bifrost-1's experimental protocol exactly (see §7) so results are directly comparable.

## 2. Baseline recap — Bifrost-1

- Bridge medium: **patch-level CLIP latents** that are *natively aligned* with the MLLM's
  own CLIP visual encoder (this alignment is the key efficiency win — beats VAE/SigLIP variants).
- MLLM gains a **visual generation branch**: a trainable copy of the MLLM's QKV/MLP/norm
  layers plus a new linear *vision head*. It predicts the (masked) CLIP latents.
- The latents condition a **latent ControlNet** adapted from FLUX.1-dev's ControlNet, which
  guides the frozen FLUX renderer.
- **Decoupled training**: MLLM branch (MSE loss on latents) and ControlNet (flow-matching
  loss) trained separately. MLLM backbone frozen → understanding preserved.

## 3. Diagnosed weaknesses of Bifrost-1

1. **MSE on continuous latents → mode-averaging.** §3.3 states "we use the MSE loss for
   image patch embedding prediction"; MAR's per-token diffusion head is dropped. MSE on a
   multimodal target regresses to the conditional mean → blur, low diversity. Likely a
   contributor to weak FID (COCO 34.35 / MJHQ 16.21 at 7B).
2. **Continuous bridge abandons the LLM-native interface** — no cross-entropy, no
   temperature/top-p sampling, no token-level **classifier-free guidance (CFG)**, no exact
   likelihood, harder RL/preference tuning. CFG is a known lever for prompt alignment
   (GenEval/DPG, where Bifrost trails).
3. **Semantic bottleneck of CLIP latents caps fidelity.** A single CLIP vector per patch is
   lossy for low-level texture/detail; reconstruction can only be pushed by scaling tokens.
4. **Exposure bias.** The ControlNet is trained on *ground-truth* CLIP latents but receives
   *MLLM-predicted* (MSE-blurred) latents at inference → train/inference mismatch.
5. **Fixed, uniform token budget.** Flat and detailed images get identical token counts.

## 4. Bifrost-Flow — the algorithm

**One line:** *adaptive-depth residual quantization of MLLM-native CLIP latents, generated by
a hybrid (discrete codes + flow-matching residual) head, and rendered by a flow-matching
model (FLUX) through a flow-matching latent ControlNet.*

Locked design decisions:
- **Renderer:** FLUX.1-dev (already a rectified-flow model) + flow-matching latent ControlNet.
  Keeps the "bridge a pretrained model" efficiency thesis. *No DDPM-style diffusion anywhere.*
- **Latent head:** **hybrid** — discrete adaptive RVQ codes (cross-entropy) **and** a
  flow-matching head for the continuous residual.
- **Adaptive depth from v1.**

### 4.1 Component A — Adaptive RVQ-CLIP tokenizer

Encode an image with the **frozen MLLM CLIP encoder** `E` to get patch latents
`z ∈ R^{N×d}` (N patches). Residual-quantize each patch with a **shared codebook**
`C ∈ R^{K×d}` to an **adaptive depth** `d_p` per patch:

```
r_0 = z_p
for k = 1..D_max:
    c_k   = argmin_j || r_{k-1} - C[j] ||         # nearest code
    r_k   = r_{k-1} - C[c_k]                        # residual
    halt? = gate(r_k, k)                            # stop if residual small / gate fires
ẑ_p = sum_{k=1..d_p} C[c_k]                          # dequantized prefix
res_p = z_p - ẑ_p                                    # continuous remainder (for flow head)
```

- **Adaptive depth** via a halting gate driven by residual norm / a learned importance map
  (cf. VRVQ). High-detail patches spend more codes; flat patches stop early. A per-patch
  `<halt>` symbol marks termination so the MLLM can predict variable depth.
- **Codebook:** EMA updates, commitment loss, entropy regularization against collapse.
- The **dequantized latent** `ẑ` is a finite-vocabulary representation; the **residual**
  `res` is the continuous detail handed to the flow-matching head.

Losses (Stage 0): `||z - (ẑ+res)||` reconstruction (here res is teacher residual), commitment,
codebook-entropy, and a depth/rate penalty to keep budgets honest.

### 4.2 Component B — MLLM + hybrid vision generation branch

Frozen MLLM (Qwen2.5-VL). Trainable **vision generation branch** = trainable copy of QKV,
MLP, norm layers (init from MLLM, per Bifrost / LMFusion) + two heads:

1. **Code-classifier head** (linear → K logits, per residual level): predicts the adaptive
   RVQ code sequence with **cross-entropy**, including the `<halt>` symbol → adaptive depth.
   Enables temperature/top-p sampling and **classifier-free guidance** (text-dropout training).
2. **Flow-matching residual head** (small MLP, NextStep-1 style): conditioned on the MLLM
   hidden state + the predicted dequantized prefix `ẑ_p`, generates the continuous residual
   `res_p` via the **flow-matching (conditional-OT velocity) objective** — replacing Bifrost's
   MSE.

**Attention masking** (from Bifrost Appendix A): causal mask for text & image-understanding
tokens; image-generation tokens use **bidirectional** attention and may attend jointly over
all token types. Generation branch processes only the Img-G tokens; frozen MLLM processes
text + Img-U.

**Decoding:** MAR-style masked autoregression over **discrete** code positions (random order,
iterative unmask), then the flow head fills the residual. CFG applied on the code logits.

### 4.3 Component C — Flow-matching latent ControlNet + FLUX renderer

As in Bifrost: adapt FLUX.1-dev ControlNet — replace the input projection (`3×d → d'×d`),
add a 2D downsampling conv (×2). Train only a few MM-DiT + Single-DiT blocks. Condition on
the **dequantized + flow-refined latent** `ẑ + res`. Trained with the **flow-matching /
velocity loss** (rectified flow), sampled by an ODE solver.

**Exposure-bias fix:** train the ControlNet on the *dequantized code space* (and optionally
scheduled-sampling on MLLM-sampled codes), so it sees its true inference-time input
distribution. The finite code vocabulary makes this gap small by construction.

### 4.4 How each weakness is addressed

| Weakness | Fix |
|---|---|
| (1) MSE blur | flow-matching residual head (distributional) + discrete codes |
| (2) lost LLM interface | discrete codes + cross-entropy + token-level CFG |
| (3) fidelity ceiling | adaptive residual depth recovers detail |
| (4) exposure bias | renderer trained on dequantized code space / scheduled sampling |
| (5) fixed budget | per-patch adaptive depth (halting gate) |

## 5. Training (decoupled)

- **Stage 0:** train the adaptive RVQ-CLIP tokenizer on CLIP latents (cheap).
- **Stage A:** MLLM vision branch — cross-entropy (codes + halt) + flow-matching (residual),
  with text-dropout for CFG. MLLM backbone frozen.
- **Stage B:** flow-matching latent ControlNet — velocity loss on dequantized code space.

## 6. Inference

```
text → MLLM (frozen) + gen branch
     → MAR decode adaptive RVQ codes (CFG) → dequantize ẑ
     → flow-matching residual head → res
     → latent ControlNet(ẑ+res) → FLUX flow ODE solve → image
```

## 7. Experimental protocol (match Bifrost-1) + new ablations

- **ImageNet-256:** FID, sFID, IS.
- **Reconstruction scaling:** rFID, SSIM, PSNR, LPIPS — as a function of **adaptive depth**
  (our analog of Bifrost's token-count Fig. 4).
- **Open-prompt:** COCO-30k FID, MJHQ-30k FID, GenEval, DPG-Bench.
- **Understanding (preserved):** MME-P, MMB, SEED, MMMU, MM-Vet (identical to backbone since
  MLLM is frozen).
- **New ablations:** residual depth `D_max`; adaptive vs. fixed depth; codebook size `K`;
  shared vs. per-depth codebooks; CFG scale; exposure-bias training on/off; flow-residual head
  on/off; and a **head-to-head Bifrost-Flow vs. Bifrost (continuous + MSE)** under matched compute
  (extends Bifrost Table 1).

## 8. Prior art & novelty

- **Bifrost-1** (2508.05954) — continuous CLIP latents + latent ControlNet + FLUX, MSE branch. *Baseline.*
- **NextStep-1** (2508.10711) — AR + continuous tokens + flow-matching head; VAE-style tokens,
  not CLIP-native, single-arch, no quantization. *We borrow the flow head; differ on bridge + RVQ.*
- **ResGen** (2412.10208) — RVQ tokens, **fixed depth**, discrete-diffusion prediction. *We add
  adaptive depth, CLIP-native bridge, flow matching.*
- **VRVQ / RAQ** (2405.14222) — variable-rate RVQ (importance map) / adaptive codebook size,
  for audio/compression. *We adapt per-patch depth for an MLLM image bridge.*
- **FlowAR** (2412.15205) — scale-wise AR + flow matching, from scratch, not CLIP/MLLM-bridge.

**Novel combination:** (MLLM-native CLIP bridge) × (adaptive-depth RVQ) × (flow matching for
both the latent residual head and the renderer). No prior work unites all three.

## 9. Engineering principle

Every component is **config-selectable** between a *tiny* variant (CPU-runnable, for tests and
end-to-end smoke runs here) and a *real* variant (Qwen2.5-VL + FLUX.1-dev on GPU). The full
training/inference loop must run on CPU with tiny dummy backbones so each phase is testable.
