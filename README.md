# AdaRQ-Flow

**AdaRQ-Flow** studies the interface between two frozen foundation models: a multimodal
LLM that reasons, and a flow-matching renderer that synthesizes. Its thesis is that this
interface should be **rate-adaptive and hybrid** — a variable-length discrete code the
reasoner can sample and guide, plus a continuous residual generated by a distributional
model that restores what quantization discards.

> [`NOVELTY.md`](NOVELTY.md) states the problem and contribution;
> [`EXPERIMENTS.md`](EXPERIMENTS.md) is the falsification plan (every claim has a kill
> criterion); [`DESIGN.md`](DESIGN.md) is the architecture; [`ISSUES.md`](ISSUES.md)
> lists defects that block quantitative claims. Tiny configs run on CPU; real backbones
> (Qwen2.5-VL + FLUX.1-dev) plug in via config on GPU nodes.

## Core idea

An interface between frozen models has three properties: its **rate** (bits per image
region), its **algebra** (what the reasoner can do with it), and its **objective** (how it
is fit). Existing bridges fix all three badly — and share one unexamined assumption: that
every region of every image deserves the same capacity.

| Property | Continuous bridges | Discrete-token bridges | AdaRQ-Flow |
|---|---|---|---|
| **Rate** | fixed, uniform | fixed, uniform | **content-adaptive per patch** |
| **Algebra** | none — no sampling, no CFG, no likelihood | full | **full (discrete prefix)** |
| **Objective** | regression → conditional mean → blur | cross-entropy, capped by quantization error | **CE on codes + flow matching on the residual** |
| **Fidelity ceiling** | mode-averaging | quantization error | residual restores discarded detail |

Two properties are **structural**, not incremental — no fixed-rate bridge achieves them at
any hyperparameter setting: **inference-time rate control** (one model spans a
rate–quality curve) and a **guidable, samplable interface** (CFG, temperature,
confidence-ordered decoding).

Everything generative is **flow matching** — no DDPM-style diffusion anywhere. The only
discrete/cross-entropy part is the adaptive code prediction, which is exactly what buys
the LLM-native interface, classifier-free guidance, and adaptive token budget.

## Architecture (4 components)

1. **Frozen MLLM** (Qwen2.5-VL) — unchanged, so understanding benchmarks are preserved.
2. **Adaptive RVQ-CLIP tokenizer** — residual-quantizes MLLM-native CLIP patch latents to
   an adaptive per-patch depth.
3. **Vision generation branch** — trainable copy of the MLLM (QKV/MLP/norm) with a
   *code-classifier head* (cross-entropy, adaptive depth + CFG) and a *flow-matching
   residual head* (continuous detail).
4. **Flow-matching renderer** — FLUX.1-dev (rectified flow) conditioned via a flow-matching
   **latent ControlNet** on dequantized + flow-refined latents.

## Layout

```
adarq_flow/
  config.py        # dataclass configs + tiny/base presets
  tokenizer/       # adaptive RVQ-CLIP tokenizer
  mllm/            # frozen MLLM + vision generation branch (hybrid head)
  renderer/        # flow-matching latent ControlNet + FLUX renderer
  training/        # decoupled training (tokenizer -> branch -> renderer)
  inference/       # text -> codes -> dequant+flow refine -> render
  eval/            # FID/sFID/IS, rFID/SSIM/PSNR/LPIPS, GenEval, DPG-Bench
  data/            # ImageNet / BLIP3-o loaders
  utils/
configs/           # experiment.yaml + ablations/ (all real models, real data)
levelb/            # Level B: Bifrost-1 protocol on ImageNet-256 (upstream modules)
scripts/           # SLURM jobs for vhpc01 (H200 only)
tests/             # unit tests; tests/fixtures/configs holds the dev-only configs
```

## Real models and real data only

Development stand-ins (dummy MLLM, dummy CLIP encoder, dummy FLUX DiT, dummy dataset) and
tiny random checkpoints exist **only for the unit tests**. Their constructors call
`adarq_flow.standins.require_test_context`, which raises unless `ADARQ_ALLOW_STAND_INS=1`
— set solely by `tests/conftest.py` and `levelb/tests/conftest.py`. No script, job or
notebook can build one. Real runs use `configs/experiment.yaml` (`run_mode: experiment`,
which additionally rejects any stand-in id) or the Level B jobs, which accept only the
official Qwen2.5-VL checkpoints.

```bash
pip install -e ".[dev,torch]"
pytest -q                                    # unit tests (the only place stand-ins exist)
python -m adarq_flow.config --print qwen2_5_vl_3b   # inspect a real config preset
```

## Training, inference, eval

Decoupled training (Stage 0 tokenizer → A branch → B renderer), distributed-aware:

Real data only. Every training run goes through `scripts/train_real.py` with a
`run_mode: experiment` config (real Qwen2.5-VL, real FLUX.1-dev, real images + captions);
the old development CLI (`python -m adarq_flow.training.train`) refuses to run, since it
could only train on the dummy dataset. Jobs run on vhpc01 H200s via SLURM.

```bash
python scripts/train_real.py --config configs/experiment.yaml --stage tokenizer   # Stage 0
python scripts/train_real.py --config configs/experiment.yaml --stage branch      # Stage A
python scripts/train_real.py --config configs/experiment.yaml --stage renderer    # Stage B
```

Generation for experiments runs through the Level B sampler (real Qwen2.5-VL and
FLUX.1-dev, real class prompts); the old demo CLI (`python -m adarq_flow.inference.generate`)
refuses to run, since it only ran the dummy preset on random token ids.

Ablation configs are in `configs/ablations/`, all derived from `configs/experiment.yaml` (real models, real data), and are run via `scripts/train_real.py --config`. They include
the **{codes on/off} × {flow/mse} factorial** used to separate "discrete codes help" from
"the distributional objective helps", at identical head capacity. Every ablation is guarded
by `tests/test_ablations_effective.py`, which asserts the mechanism is actually removed —
an ablation whose flag is ignored silently fabricates a null result.

## Development

```bash
make install     # pip install -e ".[dev,torch]"
make check       # ruff + mypy + pytest (mirrors CI)
make fmt         # ruff autofix
```

CI (`.github/workflows/ci.yml`) runs ruff, mypy, and the CPU test suite (incl. the
2-process gloo distributed test) on Python 3.10–3.12. The package ships `py.typed`.

## Status — read before citing any number

- **No quantitative claim is supported yet.** The thesis is decided only by the trained
  system on held-out test data under Bifrost-1's own protocol (`EXPERIMENTS.md`,
  "Protocol"): Level A reproduces the released Bifrost-1 checkpoint with its official
  script; Level B retrains Bifrost-1 and trains AdaRQ-Flow on ImageNet-256 with identical
  backbones, data and evaluation. E0 is a pre-flight pilot and decides nothing.
- **Everything that runs uses real models and real data**: Qwen2.5-VL, FLUX.1-dev,
  ImageNet-1k / COCO, the benchmarks' own prompts and scorers. Stand-ins are confined to
  the unit tests by a hard lock (see above). Open blockers are tracked in
  [`ISSUES.md`](ISSUES.md).
